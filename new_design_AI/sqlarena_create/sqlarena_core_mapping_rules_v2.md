# SQLArena AI — Quy tắc tạo `sqlarena_db` và xuất 2 file SQL độc lập (v2)

## 1. Mục tiêu, ranh giới

Xây **một PostgreSQL database mới tên `sqlarena_db`**, schema `core`, đúng 4 bảng: `worlds`, `skills`, `templates`, `source_questions`. Đây là **database quản lý câu hỏi**, độc lập với **database luyện SQL đang có tên `enterprise_db`**.

**Sản phẩm quan trọng nhất: CHÍNH XÁC 2 file SQL bàn giao để có thể dựng lại phần Core từ đầu mà không cần chạy Python hoặc đọc JSON lúc import:**

1. **`01_create_sqlarena_core.sql`** — chỉ DDL tạo `core` và 4 bảng, PK/FK/CHECK/index liên quan; không chèn dữ liệu.
2. **`02_insert_sqlarena_core_data.sql`** — chỉ dữ liệu đã trích từ nguồn (INSERT cho `worlds`, `skills`, `source_questions`; `templates` để trống); có transaction, không DDL, không DROP/TRUNCATE/DELETE/UPDATE dữ liệu nghiệp vụ; chạy trên database `sqlarena_db` **đã có schema vừa tạo**.

Tạo database vật lý `sqlarena_db` **một lần riêng** qua pgAdmin (Create Database) hoặc `createdb`/kết nối bảo trì `postgres`, vì `CREATE DATABASE` không được chạy bên trong transaction và Query Tool phải được kết nối đúng DB. README cần nêu thao tác này. Agent có thể chủ động tạo DB nếu có quyền, nhưng **không tự xóa hoặc overwrite DB đã tồn tại**. Hai file SQL nói trên là hai artifact chính; không tạo một file seed Python bắt buộc để import.

Nguồn thông tin:
- `questions_validated.json`: nguồn chuẩn của 50 câu (văn bản, reference SQL, metadata, validation).
- `enterprise_50_question_rules_v1.md` (hoặc file Rules cùng nội dung): taxonomy S1–S6, mức khó, quota 20 Easy / 20 Medium / 10 Hard, 5 domain.
- `schema_code.sql` (kể cả ALTER cuối file), `constraint.sql`, tài liệu BR01–BR16; ưu tiên cấu trúc thật trong `enterprise_db` khi có kết nối chỉ đọc để lấy metadata chính xác.
- *Tổng kết kiến trúc*: tên 4 bảng và vai trò.

Không tạo dữ liệu mới cho `enterprise_db`, không chạy Generator, không chạy seed, **không viết lại hoặc tạo lại 50 câu**, không sửa tài liệu/SQL nguồn. Không tạo schema `draft` hoặc `live` lúc này.

## 2. `world_id` và kết nối DB

- `core.worlds.world_id = 'enterprise_v1'` — **mã logic** được lấy nguyên từ JSON, không phải tên PostgreSQL database.
- `core.worlds.database_name = 'enterprise_db'` — tên database PostgreSQL thật, dùng cho việc tra cứu cấu hình kết nối sau này.
- `sqlarena_db` chỉ lưu đề/metadata, **không chứa 16 bảng nghiệp vụ**. Backend tương lai tra `world_id`, ánh xạ tới database cho phép rồi mở kết nối riêng đến `enterprise_db` bằng tài khoản **chỉ đọc**. Không có FK xuyên database.
- Không lưu mật khẩu, DSN có mật khẩu hay token trong bảng hoặc trong 2 file SQL.

## 3. Thiết kế 4 bảng, kiểu dữ liệu gợi ý và nguồn dữ liệu

### 3.1. `core.worlds` — kỳ vọng 1 dòng

| Cột | PostgreSQL | Cách nạp |
|---|---|---|
| `world_id` | `varchar(100) PRIMARY KEY` | `'enterprise_v1'`, trùng với mọi `world_id` trong JSON |
| `name` | `varchar(150) NOT NULL` | `'EnterpriseDB v1'` (tên hiển thị) |
| `database_name` | `varchar(100) NOT NULL` | `'enterprise_db'` |
| `dialect` | `varchar(30) NOT NULL` | `'postgresql'` |
| `schema_description` | `jsonb NOT NULL` | Mô tả đúng bảng/cột/kiểu dữ liệu/PK/nullable của World hiện có |
| `fk_relations` | `jsonb NOT NULL` | Danh sách FK đúng với World hiện có |
| `business_rules` | `jsonb NOT NULL` | BR01–BR16 theo tài liệu; lưu rõ nguồn. Nếu không có mô tả đầy đủ: báo thiếu, **không bịa** |
| `planted_traps` | `jsonb NOT NULL DEFAULT '[]'::jsonb` | Chỉ scenario/edge case đã được xác minh; nếu không có, `[]` |
| `allowed_sql_features` | `jsonb NOT NULL` | Nhóm lệnh SELECT, JOIN, aggregate, subquery, window, CTE, recursive theo Rules |

Nếu tài liệu BR hoặc schema metadata không thể đọc đầy đủ, **không giả vờ đủ**. Nêu rõ giới hạn trong báo cáo; có thể hoãn nạp dữ liệu world hoặc dùng cấu trúc JSON mô tả tình trạng thiếu nguồn một cách minh bạch, nếu được thống nhất; tuyệt đối không sáng tác BR.

### 3.2. `core.skills` — kỳ vọng 6 dòng

| Cột | PostgreSQL | Nguồn |
|---|---|---|
| `skill_id` | `varchar(30) PRIMARY KEY` | S1–S6 |
| `name` | `varchar(160) NOT NULL` | Nhãn chuẩn từ Rules |
| `category` | `varchar(100) NOT NULL` | Nhãn nhóm có quy ước rõ (ví dụ `SQL_READ`) |
| `base_difficulty` | `varchar(10) NOT NULL CHECK IN (...)` | S1 easy, S2 easy, S3 easy, S4 medium, S5 medium, S6 hard; **chỉ là mức nền tham khảo** |

Không nhầm `base_difficulty` với độ khó từng câu.

### 3.3. `core.templates` — kỳ vọng **0 dòng**

| Cột | PostgreSQL | Vai trò |
|---|---|---|
| `template_id` | `bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | ID |
| `world_id` | `varchar(100) NOT NULL REFERENCES core.worlds(world_id)` | World chứa template |
| `topic` | `varchar(150) NOT NULL` | Chủ đề |
| `difficulty` | `varchar(10) NOT NULL CHECK IN (...)` | Mức khó |
| `pattern` | `text NOT NULL` | Khung sinh câu (không phải câu đã tạo) |
| `constraints` | `jsonb NOT NULL DEFAULT '{}'::jsonb` | Ràng buộc template |

**Không tạo 50 template giả từ 50 câu nguồn.**

### 3.4. `core.source_questions` — kỳ vọng **50 dòng**

| Cột | PostgreSQL | Ánh xạ từ JSON |
|---|---|---|
| `question_id` | `varchar(30) PRIMARY KEY` | `question_id` ENT-001...ENT-050 |
| `world_id` | `varchar(100) NOT NULL REFERENCES core.worlds(world_id)` | `world_id` |
| `title` | `text NOT NULL` | `title` |
| `question_text` | `text NOT NULL` | `question_text` — **giữ nguyên byte/nội dung** |
| `reference_sql` | `text NOT NULL` | `reference_sql` — lưu như TEXT, **không thực thi trong script import** |
| `difficulty` | `varchar(10) NOT NULL CHECK IN (...)` | `difficulty` |
| `primary_skill_group` | `varchar(30) NOT NULL REFERENCES core.skills(skill_id)` | `primary_skill_group` |
| `primary_business_domain` | `varchar(100) NOT NULL` | `primary_business_domain` |
| `skills` | `jsonb NOT NULL DEFAULT '[]'::jsonb` | `secondary_skills` (đúng mảng gốc; primary đã có cột riêng) |
| `depth` | `integer CHECK (depth IS NULL OR depth >= 0)` | V1 dùng `0` nếu định nghĩa rõ là **generation depth của nguồn gốc** (không đồng nghĩa viết tay), lưu `origin=ai_assisted_baseline` trong metadata; nếu chưa thống nhất thì `NULL` |
| `metadata` | `jsonb NOT NULL` | Các field còn lại của câu, ít nhất `taxonomy_version`, `business_goal`, `output_grain`, `tables_used`, `difficulty_reason`, `logic_signature`, `output_columns`, `edge_cases`, v.v. |
| `validation` | `jsonb NOT NULL` | Nguyên object `validation`, gồm PASS/row_count/hash/runtime... |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | Thời điểm import, **không giả làm thời điểm tạo câu** |

Giữ nguyên `questions_validated.json` gốc. Có thể giữ **toàn bộ** object gốc trong `metadata` theo key `source_json` nếu muốn đối chiếu lossless; khi đó phải nêu rõ và tránh nhập nhằng với các cột tách riêng. Ưu tiên cách lưu từng metadata còn lại và so sánh nguyên vẹn. SQL chứa Unicode tiếng Việt và `reference_sql` nhiều dòng; phải encode UTF-8 và escape đúng để không lỗi `'`, `$`, `\` hoặc JSONB.

## 4. Quan hệ và ràng buộc

- `worlds (1) → (N) source_questions` qua `world_id`.
- `worlds (1) → (N) templates` qua `world_id`.
- `skills (1) → (N) source_questions` qua `primary_skill_group`.
- `CHECK difficulty IN ('easy','medium','hard')`; PK unique và FK thực tế; `depth >= 0` nếu không NULL.
- Có thể thêm index phục vụ tra cứu `world_id`, `difficulty`, `primary_skill_group`, `primary_business_domain` (không vượt phạm vi 4 bảng).
- Không có FK đến `enterprise_db`, cũng không có bảng join liên DB.

## 5. Quy tắc bắt buộc của **hai file SQL**

### File 1 — `01_create_sqlarena_core.sql`

- Chỉ tạo `SCHEMA core` và 4 TABLE + constraints/index trên **DB đang được kết nối là `sqlarena_db`**.
- Bọc trong transaction khi phù hợp; có thể `CREATE SCHEMA IF NOT EXISTS`; **không DROP** hoặc sửa bảng đã có theo cách phá hủy.
- Không `CREATE DATABASE` trong file này; README hướng dẫn tạo riêng đúng cách.
- Không INSERT bất kỳ dữ liệu nào.
- Khi chạy lại, không phá cấu trúc/dữ liệu cũ; nếu bảng đã tồn tại nhưng cấu trúc khác, dừng có giải thích, không lặng lẽ bỏ qua sự khác biệt.

### File 2 — `02_insert_sqlarena_core_data.sql`

- **Là SQL tự chứa**: toàn bộ 1 world + 6 skills + 50 questions được materialize thành INSERT literal; chạy trực tiếp trong pgAdmin Query Tool trên `sqlarena_db` sau file 1, **không cần file JSON, Python, `\copy`, extension hay trình tạo khác lúc thực thi**.
- Chỉ chèn dữ liệu mới vào 3 bảng, để `templates` rỗng. Thứ tự `worlds` → `skills` → `source_questions` (templates không insert).
- Dùng `BEGIN; ... COMMIT;` để import nguyên tử; file chạy lại phải **từ chối an toàn trước khi thay đổi** nếu Core đã chứa bất kỳ dữ liệu nào; không âm thầm duplicate/overwrite. Có thể dùng `DO $$ ... RAISE EXCEPTION` để chặn và rollback toàn transaction khi dữ liệu không trống; thông báo dễ hiểu.
- **Không dùng** `DROP`, `TRUNCATE`, `DELETE`, `UPDATE` để reset dữ liệu; **không chạy** `reference_sql` (chỉ lưu nó vào cột text).
- Escape quote đúng: dùng SQL string escaping hoặc dollar-quoting với delimiter đủ riêng cho từng payload; JSONB insert bằng text literal UTF-8 `::jsonb` có kiểm tra parse; không viết placeholder như `...`.
- Có thể đặt các câu SELECT xác minh ở cuối file sau COMMIT, nhưng **câu cuối nên là SELECT tổng số bản ghi theo 4 bảng** để pgAdmin dễ xem; bên cạnh đó có truy vấn quota riêng trong README.
- **Không tự tạo `enterprise_db` hoặc nạp lại seed.**

### Cách chạy sau này (không cần Agent/Python)

1. Tạo database trống `sqlarena_db` qua pgAdmin/`createdb`.
2. Mở Query Tool **kết nối vào `sqlarena_db`**, chạy toàn bộ `01_create_sqlarena_core.sql`.
3. Vẫn trên `sqlarena_db`, chạy toàn bộ `02_insert_sqlarena_core_data.sql`.
4. Chạy SELECT kiểm tra counts, FK và quota. **Kỳ vọng 1 / 6 / 0 / 50**.

## 6. Quy tắc Agent kiểm chứng đầu vào và kết quả

1. Đọc JSON array thực tế, đếm **đúng 50** câu, ID duy nhất ENT-001...ENT-050, all world_id `enterprise_v1`; không tự sửa câu nguồn.
2. Kiểm tra mọi câu có title, question_text, reference_sql, difficulty, primary skill, domain, validation PASS và `sql_executed=true`. PASS chỉ là **thông tin đã lưu trong JSON**, không tuyên bố tự chạy lại nếu không làm.
3. Kiểm tra quota: Easy 20, Medium 20, Hard 10; S1 8, S2 10, S3 10, S4 7, S5 10, S6 5; domain 8/13/12/9/8 theo Rules.
4. Xác minh metadata `worlds` bằng tài liệu và nếu được phép thì chỉ đọc `enterprise_db` bằng SELECT/catalog. **Không thực thi SQL câu hỏi để import.**
5. Tạo 2 file SQL hoàn chỉnh, kiểm tra trong file 2 có chính xác 50 dòng câu nguồn và không bỏ trường quan trọng.
6. Nếu có quyền, tạo **database mới** `sqlarena_db` rồi chạy file 1, file 2 đúng thứ tự. Nếu `sqlarena_db` đã tồn tại, chỉ được dùng khi được xác nhận đang trống và tương thích; **không reset, DROP hoặc overwrite**.
7. Chạy SQL read-only kiểm tra số dòng 1 / 6 / 0 / 50, FK orphan=0, các quota và đối chiếu từ DB với JSON: `question_text`, `reference_sql`, `validation`, metadata. Nếu có sai khác, báo FAIL, không sửa nguồn cho khớp.
8. Báo cáo rõ đã chạy thành công hay chỉ tạo file. Nếu không có quyền/kết nối PostgreSQL, **không bịa PASS**.

## 8. Bàn giao

**Bắt buộc:**
- `01_create_sqlarena_core.sql` — file **tạo cấu trúc** (DDL).
- `02_insert_sqlarena_core_data.sql` — file **chèn dữ liệu hoàn chỉnh** (DML), tự chứa và chạy trực tiếp.

**Kèm theo:**
- `sqlarena_database_guide.md` — hướng dẫn tạo database, chạy hai file đúng Query Tool, kiểm tra kết quả.

Nếu cần Agent dùng Python để **sinh ra file 02 từ JSON**, có thể viết script nội bộ tùy chọn, nhưng **không được biến nó thành bước bắt buộc khi người dùng muốn import bằng hai file SQL**.
